# 视频任务工作流 PRD v3.0（最终评审版）

## v4.0 内容驱动画面与预览审批修订（已实施）

- 成片阶段调整为：**选择视觉风格 → 自动生成 10 秒真实动态预览 → 确认效果 → 正式渲染**。不再多选模板后直接生产；多种风格逐个预览、逐个生成并分别保存。
- 预览抽取 2–3 个代表性真实分镜，保留对应配音和字幕；预览与正式渲染共用 Composition、Storyboard、风格 Props、素材清单、引擎版本和固定随机种子，只允许降低分辨率与编码码率。
- 新增 `visual_previews` 持久化表和 `video.preview` 队列任务，记录模板版本、请求、Storyboard、Props、输入快照、内容指纹、进度、视频/封面文件、错误、当前状态和审批时间。页面刷新及进入后续状态后仍可查看历史。
- 指纹覆盖文稿及版本、音频、SRT、素材、模板与 Props、场景引擎版本和 9:16 输出参数。修改任一输入后，`/render` 与 `/produce` 均要求当前指纹存在已审批预览，否则返回 409；正式渲染直接读取审批时保存的 Props。
- 新增确定性 Storyboard 引擎：按真实字幕/文稿切分场景，识别 `hook/key_point/metric/process/comparison/timeline/architecture/map/media/quote/cta`，明确步骤词优先于数字识别；失败时使用安全动态场景，不临时生成 Remotion 代码。
- 企业 AI、科技、地图、情感、创始人 IP 和宣传广告六类模板共享内容数据与场景类型，但使用独立版式组件：创始人杂志大字、企业业务仪表盘、科技终端/HUD、情感纸张金句、宣传斜切卖点、地图全屏路线；风格包同时控制配色、字体、背景、字幕和动效，不再只换颜色。数据、音频、卡拉 OK 和动感文字模板保留既有专用 Composition。
- 每个较长场景按 2.8 秒设置视觉节拍：数字/图表增长、流程推进、路径连线、镜头运动、对比揭示、元素重组或媒体切换。字幕逐字、背景微变色和粒子循环不能单独算作有效节拍；验收必须对实际渲染抽帧，不只检查 JSON。
- 默认智能混合：无素材使用程序化动态图形，有授权图片/视频时自动运镜、裁切和包装；纯上传模式没有视觉模板选择，保留直接 FFmpeg 渲染。未配置外部生成模型时不调用付费 AI 素材服务。
- 新增接口：`POST/GET /api/tasks/{id}/visual-previews`、`GET /api/tasks/{id}/visual-previews/{preview_id}`、`POST /api/tasks/{id}/visual-previews/{preview_id}/approve`。预览媒体作为 `preview_video/preview_cover` 文件保存在 `previews/{task_id}`，与正式成片隔离。

- 素材清单在全部 Remotion 模式下默认折叠为可选项。

## 1. 背景与问题定义

现有视频任务已经具备脚本生成、真人/系统/克隆录音、SRT、素材授权、Remotion/FFmpeg、固定模板、多模板渲染、质检、发布和本地文件能力，但真实使用仍存在四类问题：

1. **流程违背用户目标**：用户希望选择内容后自动得到视频，却必须逐步操作后端状态机。
2. **文稿生成僵化**：一次强制生成母稿、三个视频版本和公众号文章；母稿被强制要求，手填内容易被批量生成覆盖。
3. **版本与审批存在风险**：多个视频共用任务级质检，发布固定读取最新 MP4；音频与 SRT 只检查是否存在，可能错配。
4. **速度与环境切换成本过高**：长文稿单次生成、CPU 转写、每个模板重复打包渲染；进入下一阶段后无法回看上一阶段，保存或刷新还可能丢失未保存内容。

本版不重做选题、文章、账号日报和发布中心，只改造视频任务主链路及其必要接口。

### 1.1 已确认的现状证据

- 脚本校验一次强制五个字段，单次模型调用同时承担长母稿、三个视频版本和完整公众号文章的输出。
- Agent 设置存在模型字段，但当前脚本调用仍使用 Kimi CLI 默认模型，速度/质量配置没有形成真实路由。
- WhisperX 使用 faster-whisper CPU 转写，默认 `small`、两个计算线程，长音频需要等待。
- 多模板逐个执行 Remotion CLI；真实验收中两段仅 2 秒的视频合计约 116 秒，重复 Bundle 和渲染环境启动是必须消除的结构性开销。
- 历史阶段仅由当前状态驱动展示；`updated_at` 作为阶段组件 key，会在保存或刷新后重建页面并丢失部分本地操作状态。

## 2. 产品目标与非目标

### 2.1 产品目标

- 用户可输入视频、热点、主题或文章，也可以从现有选题直接创建视频任务。
- 文稿支持全 AI、全手填和混合输入；母稿不是必填项。
- 批量生成只补空缺，任何手填内容默认不被覆盖。
- 写作 Agent 可配置并自动加载“去 AI 味儿”和“写作技巧”Skills。
- 一次点击后自动完成配音、字幕、分镜、模板渲染和机器预检。
- 同一套内容可生成多个不同风格视频并全部保存到本地。
- 每个视频版本独立预览、质检、审批、发布和下载。
- 已进入过的阶段始终可回看，历史阶段默认只读。
- 长任务有真实进度、取消、恢复和失败重试；相同输入不重复生成或渲染。

### 2.2 非目标

- 不做通用视频剪辑器或在线 React 代码编辑器。
- 不要求所有内容都使用 AI 生成，也不以 AI 生成替代人工事实判断。
- 不为了自动化取消声音授权、素材授权和公开发布前终审。
- 不承诺所有平台均可无人值守自动发布。
- 不在本期一次性上线所有地图、手绘、广告模板；先保证模板框架和主流程正确。

## 3. 核心设计原则

1. **手填优先**：手工输入是最高优先级约束，批量 AI 只补空缺。
2. **当前需要优先**：默认只生成当前平台需要的文稿，不强制五版，不强制母稿。
3. **一次内容，多次视觉渲染**：文稿、音频、SRT 和语义分镜共享，模板分别渲染。
4. **历史永不消失**：进入下一阶段不删除、不隐藏上一阶段成果。
5. **版本精确绑定**：音频绑定 SRT，视频绑定质检与审批，发布绑定具体文件。
6. **自动但不失控**：本地草稿可全自动，公开风险仍需人工确认。
7. **性能必须可测**：所有优化记录真实耗时、调用次数、Bundle 次数和缓存命中。

## 4. 顶层 Agent 编排与内部流程

### 4.1 顶层协作流程

```text
选题 Agent ─┐
            ├─ 标准化 VideoBrief
人工输入 ───┘        │
                     ▼
          ┌──────────────────────────┐
          │      视频生成 Agent       │
          │ 内容 → 文稿 → 制作方案    │
          │ → 自动生产 → 多版本结果   │
          └──────────────────────────┘
                     │ VideoPackage
                     ▼
                审核路由
          ┌──────────┼──────────┐
          │          │          │
      审核 Agent   人工审核    不审核
          └──────────┼──────────┘
                     ▼
                发布 Agent
          ┌──────────┼──────────┐
       人工发布    策略自动发布   仅保存本地
```

视频生成 Agent 是编排器，不是一次巨大的模型调用。内部复用脚本、TTS/OpenVoice、WhisperX、分镜、Remotion/FFmpeg 和机器预检能力；用户只需理解“视频正在生成”。

**中心与 Agent 的关系**：选题中心展示选题 Agent 的候选、证据和已推送任务，负责选择与编辑；发布中心展示发布 Agent 的发布候选、平台预览、队列和结果，负责确认与异常处理。Agent 负责生产和执行，中心负责查看与决策，二者共用同一任务数据。

### 4.2 VideoBrief 输入契约

```json
{
  "source": {"type": "topic_agent|manual_topic|article|video", "references": []},
  "title": "企业 AI 落地为什么容易失败",
  "content": "人工提供的内容，可为空",
  "audience": "企业主",
  "platform": "douyin",
  "constraints": {"tone": "直接、具体", "duration_seconds": 90, "forbidden_claims": []},
  "production_preset": "enterprise_ai_default",
  "review_mode": "agent|human|none",
  "publish_mode": "manual|auto|local_only"
}
```

### 4.3 VideoPackage 输出契约

```text
content_id + production_job_id
共享文稿、音频、字幕和分镜版本
variants[{variant_id, file_id, file_sha256, template_version, status}]
machine_review_summary
stage_timings 与缓存记录
review_mode + publish_mode
local_output_directory
```

审核与发布只能消费 VideoPackage 中明确的 Variant，不得重新查找“最新视频”。

### 4.4 视频生成 Agent 内部五阶段

用户只看到五个主阶段；内部技术步骤由后台流水线管理。

```text
01 内容 → 02 文稿 → 03 制作方案 → 04 自动生产 → 05 结果与发布
```

### 4.5 全局工作台原型

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 视频任务                                            [刷新] [新建视频任务]     │
├───────────────┬──────────────────────────────────────────────────────────────┤
│ 任务列表       │ 内容项目：企业 AI 落地为什么容易失败                         │
│               │ 来源：热点 / 文稿 / 主题 / 视频       当前：自动生产中         │
│ 我的小满       │                                                              │
│ 企业 AI 案例   │ [01 内容]—[02 文稿]—[03 制作方案]—[04 自动生产]—[05 结果]   │
│ 创始人观点     │                                                              │
│               │ 当前工作区                                                   │
│ 筛选：全部     │ ┌──────────────────────────────────────────────────────────┐ │
│ 状态：进行中   │ │ 本阶段只显示当前最重要的内容与一个主要动作               │ │
│               │ └──────────────────────────────────────────────────────────┘ │
│               │ [查看历史阶段] [操作记录]                                    │
└───────────────┴──────────────────────────────────────────────────────────────┘
```

**细节**

- 页头只保留任务名称、来源、真实状态和主要动作，长标题最多两行。
- 五阶段均可查看；能否编辑由 `currentStage` 决定，不由 `viewStage` 决定。
- 任务列表显示下一步，而不是只显示内部状态码。
- 历史记录、技术状态和 Agent 名称收进二级信息区。

## 5. 功能需求与原型

### F01 内容输入与任务创建

**目标**：支持多种内容来源，但统一成一个视频内容项目。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 新建视频任务                                                                 │
├──────────────────────────────────────────────────────────────────────────────┤
│ 内容来源  [选题/热点] [视频链接或文件] [输入主题] [粘贴文章]                  │
│                                                                              │
│ 已选择：抖音热点 #3「企业 AI 落地为什么难」                        [更换]     │
│ 来源证据：链接、快照时间、原文/视频分析状态                        [查看]     │
│                                                                              │
│ 目标平台  [抖音 ▾]     内容方向 [企业 AI ▾]     受众 [企业主 ▾]             │
│ 制作方式  ○ 全自动生成文稿  ○ 我自己填写  ○ 混合（推荐）                     │
│                                                                              │
│ 默认方案：企业 AI 常用（创始人 IP + 流程解说）                    [修改]     │
│ 审核方式 [Agent 审核 ▾]  发布方式 [仅保存本地 ▾]                            │
│                                                   [取消] [创建并继续]         │
└──────────────────────────────────────────────────────────────────────────────┘
```

**功能细节**

- 首版优先支持现有选题/热点、输入主题、粘贴文章和上传已授权视频；视频链接自动下载、抽帧与结构分析列入后续增强，不阻塞主闭环。
- 视频来源只提取观点、结构、字幕和关键帧，不默认搬运原文或原画面；用户始终可改为手工粘贴文稿。
- 热点和文章保留来源 URL、时间和证据；主题输入允许无外部资料。
- “制作方式”只影响默认行为，不限制后续手工编辑。
- 默认模板、审核和发布方案可在设置中修改，创建后仍可调整；默认“审核 Agent + 仅保存本地”，自动公开发布必须由用户显式开启。
- 创建后统一生成 `VideoBrief`，选题 Agent 与人工输入在进入视频生成 Agent 前使用同一契约。
- 来源分析失败时允许手工粘贴文稿继续，不强制重试。

**验收**：首版四种入口均可创建任务，其中上传视频可先使用已有分析结果或手工文稿；自动视频深度分析单独验收，不与主生产闭环捆绑。

### F02 文稿按需生成与混合编辑

**目标**：母稿可选，手填优先，AI 只生成当前需要且缺失的内容。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 文稿                                        [按手填内容补齐空缺] [继续制作]   │
├──────────────────────────────────────────────────────────────────────────────┤
│ 当前任务需要：抖音口播稿；母稿和其他平台版本均为可选                         │
│                                                                              │
│ [抖音口播稿（本任务使用）] [母稿（可选）] [其他平台（按需展开）]              │
│                                                                              │
│ 抖音口播稿 · 手填                                      [生成] [清空] [版本]   │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 用户已经输入的内容不会被批量生成覆盖……                                   │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 母稿 · 待补齐（非必需）                                  [生成此栏] [清空]    │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 可留空；填写后可作为其他版本的参考                                       │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 规则：手填内容优先；批量生成只补空缺；重写指定字段需确认。                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**生成规则**

| 输入情况 | 系统行为 | 主按钮 |
|---|---|---|
| 全部为空 | 只生成当前任务所需文稿 | 生成所需文稿 |
| 只有母稿 | 以母稿为约束生成当前平台口播稿 | 根据母稿生成口播稿 |
| 只有平台口播稿 | 不调用 AI，可用于配音；母稿继续留空 | 继续制作 |
| 混合输入 | 非空字段全部作为约束，只生成空字段 | 按手填内容补齐空缺 |
| 全部手填 | 不调用写作 Agent | 继续制作 |
| 明确要求重写 | 只重写指定字段；全部重写需二次确认 | 重写此栏 |

**功能细节**

- 每栏标记 `手填 / AI 生成 / AI 生成后已修改 / 待补齐`。
- 每栏支持独立生成、改写、清空和版本查看。
- 保存手工内容不触发模型。
- 当前平台口播稿存在即可继续，不再校验母稿和其他平台版本。
- 页面显示未保存提示；切换任务、刷新和生成其他字段不会丢失当前编辑。
- 批量生成采用 `preserve_manual=true`，后端也必须拒绝覆盖，不能只依赖前端。
- 每栏增加 `revision_no + base_revision + generation_request_id + content_hash`。AI 返回时执行 CAS 版本比较，防止生成期间的新手工编辑被覆盖。
- 如果 AI 返回时栏位已变化，结果只保存为“候选版本”，当前文稿不变；用户通过对比视图决定是否采用。

**异常**：单栏生成失败只标记该栏失败，其他已填和已生成内容保持不变；发生版本冲突时不算生成失败，提示“已有新编辑，AI 结果已保存为候选”。

### F09 独立质检、审批与发布

**目标**：审核与发布解耦；批准哪个文件，就只能发布哪个文件。

```text
VideoPackage
   ├─ review_mode=agent  → 审核 Agent → passed / needs_revision / requires_human
   ├─ review_mode=human  → 人工逐版本审核
   └─ review_mode=none   → 不做内容审核，保留机器技术检查
                                      ↓
publish_mode=manual / auto / local_only → 发布 Agent 或仅保存本地
```

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 质检与终审 / 创始人·口播金句 / file_id=1024                                 │
├──────────────────────────────────────────────────────────────────────────────┤
│ [当前视频预览，明确显示模板、版本和文件名]                                   │
│                                                                              │
│ 机器预检：画幅通过 / 音轨通过 / 无黑帧 / 字幕边界需复核             [详情]   │
│ 人工确认：[✓] 字幕准确 [✓] 声音清晰 [✓] 画面完整 [✓] 版权合规 [✓] 规格正确 │
│ 备注：[…………………………………………………………………………………………………………]           │
│                                                                              │

└──────────────────────────────────────────────────────────────────────────────┘
```

**功能细节**

- 质检、人工批准和发布记录必须包含 `variant_id + file_id + file_sha256`；发布前重新计算并比对文件哈希，防止审批后文件被替换。
- 发布中心接收明确文件，不再自行查询最新视频。
- 任何重新渲染都会产生新文件并使该版本旧审批失效，不影响其他模板审批。
- 支持逐版本处理；批量批准只能在每个版本都完成必要检查后执行。
- 发布前显示最终文件名称、模板版本和预览，防止错发。
- `review_mode=agent` 支持 `passed / needs_revision / requires_human / rejected`；退回时带具体 Variant、时间点、证据和修改建议，最多自动返修 1–2 次，超过后转人工。
- `review_mode=none` 只跳过内容审核，仍执行文件损坏、无音轨、黑帧、画幅等机器技术检查。
- `publish_mode=manual` 由用户确认具体文件与平台；`auto` 仅在用户明确配置的平台和方案内自动执行；`local_only` 只保存本地，不调用公开发布。
- 审核 Agent 无法判断或证据不足时必须转人工，不得强行通过。

- 记录模型调用次数、输出文稿数量、转写耗时、Bundle 次数、模板渲染次数和缓存命中。
- 每次版本升级使用同一短音频、同一 SRT 和相同双模板做基准比较。
- 不把“界面更有进度感”当成真实提速。
- 性能页不展示密钥、完整提示词或敏感素材内容。

### F13 三级配置与继承

**目标**：常用配置在任务内完成，Agent 默认值集中管理，技术细节只出现在高级入口。

```text
│ 配置中心                                                                     │

│                                                                              │
│ ② 设置 / Agent 配置 / 视频生成 Agent                                         │

│                                                                              │
│ ③ 设置 / 本地服务（高级）                                                    │
```

**功能细节**

- 生产进度不放入设置；设置只管理未来任务的默认值，不改变正在执行的 Job 快照。
- 本次任务显示关键配置来源，例如“来自企业 AI 默认方案”，并允许单独覆盖。
- Agent 配置修改形成新版本，正在执行的任务继续使用创建时配置。
- 本地服务配置仅包含技术项，不展示密钥、完整提示词或敏感内容。

### F15 平台元数据、预览与一键同步

**目标**：封面、描述、标签按平台独立处理；本地预览与实际同步使用同一参数包。

```text

│ ┌───────────────────────────┐ │ 标题：[…………………………………………]               │
│ │ 视频/封面                  │ │ 描述：[…………………………………………]               │
│ │ 标题、描述、标签           │ │ 标签：[#企业AI] [#AI落地]                   │
│ └───────────────────────────┘ │ 校验：资料完整、账号可用、文件未变化         │
```

- 元数据继承为“共享发布母版 < 发布方案预设 < 平台 Schema < 当前内容平台版本 < 用户手工修改”。
- 每个平台拥有独立标题、描述、标签、封面和 `platform_specific`；平台规则以真实表单校验，具体字数、画幅和格式不凭经验写死。
- 封面支持视频抽帧、上传、选择其他帧、裁剪和可选 AI 生成；保存独立素材与授权，缺封面只阻塞对应目标。
- 本地效果预览用于快速编辑和批量检查；可选平台真实预览由 Agent 上传并保存草稿后返回真实截图或状态。
- “同步为草稿”只填写并保存平台草稿；“一键发布”在资料、文件哈希、审核策略、登录状态和幂等检查通过后执行公开发布。
- 发布状态为 `draft / metadata_incomplete / ready / scheduled / publishing / published / failed / requires_review`；同步中不等于已发布。
- 有平台作品链接才标记 `published`；结果不明时标记 `requires_review`，禁止自动重发。
- 每个目标独立执行，单个平台结构变化或失败只暂停该平台，不阻塞其他目标。

## 7. 关键业务规则

1. 当前平台口播稿存在即可继续，母稿和其他平台文稿不参与强制校验。
2. 批量生成默认保护手填；只有明确重写操作才能覆盖。
3. 手工保存不调用模型；生成和改写必须加载配置的写作 Skills。
4. 历史阶段可访问但默认只读，返修是独立显式动作。
5. 音频与字幕必须成对使用，不能分别取最新文件。
6. 每个视频版本独立质检、审批和发布，发布接口必须传入明确 `file_id + file_sha256`。
7. 纯 Remotion 跳过上传素材授权；有素材才执行对应授权。
8. 相同输入只生成一次；相同模板代码只打包一次，但动态素材不得被打包身份混淆。
9. 本地草稿可全自动；公开发布默认人工终审，只有用户显式配置 `publish_mode=auto` 的平台与方案才可策略自动发布。
10. 所有失败必须保留成功结果并给出下一步，不要求整单重做。
11. AI 返回时若栏位已发生新编辑，只能生成候选版本，不得覆盖当前文稿。
12. 历史回看读取 `stage_revisions`，不能用当前任务 JSON 冒充阶段历史。
13. 审核方式与发布方式独立；`review_mode=none` 只跳过内容审核，不等于跳过机器技术检查，也不等于自动公开发布。
14. 批量发布按 `variant_id + platform` 独立校验、执行和回收结果，任何单目标失败不得阻塞其他目标。
15. 批量编辑只修改明确选择的字段，不能用手工已修改的平台元数据覆盖为共享默认值。
16. 本地预览与同步必须使用同一 `payload_hash`；同步为草稿与公开发布是不同动作，点击同步不得直接记为已发布。
17. 结果不明时只能标记 `requires_review`，禁止自动重发；平台链接是标记 `published` 的必要证据。

## 8. 性能与可靠性要求

### 8.1 可量化验收

- 创建生产 Job 的接口应在本地正常负载下快速返回 Job ID，而非等待完整渲染。
- 只缺少一个文稿字段时，不得调用生成五份文稿的接口。
- 输入未变化的第二次生产不得重复模型调用。
- 模板代码未变化的 N 个模板渲染最多执行一次 Bundle。
- 页面刷新不得创建新 Job，也不得丢失当前进度。
- 保留同一 2 秒样本测固定启动开销，并增加 90 秒真实口播样本测逐帧渲染与 Whisper 成本；同时比较冷启动、热缓存、单双模板和 base/small。

### 8.2 Bundle 与动态素材架构约束

- 模板代码、固定字体和品牌静态资源进入 Bundle，Bundle 身份由源代码与固定依赖哈希决定。
- 任务音频、视频、图片等动态素材通过独立本地媒体 URL 提供，Props 只传 URL，不把任务素材混入模板 Bundle 身份。
- 媒体 URL 必须校验任务归属和本地访问权限，避免跨任务读取或旧素材复用。
- 首版在现有 Worker 中使用 `@remotion/bundler` 与 `renderMedia()` 复用 Bundle；只有证据证明进程/浏览器初始化仍是主要瓶颈后，才评估常驻 Node 渲染服务。
- 常驻服务若后续引入，必须另行设计崩溃恢复、端口访问控制、资源争用和 macOS/Windows 启动方式。

### 8.3 可靠性

- 重复点击、双击和多标签页提交必须幂等。
- 失败重试不得覆盖已成功文件。
- 输出文件必须先验证音视频流再进入结果列表。
- 任何缓存命中都必须同时验证输入哈希和文件存在性。
- 质检、审批和发布前必须重新验证 `file_sha256`，不能只信任数据库路径。

## 9. 埋点与产品指标

- 文稿手填率、AI 补齐率、批量覆盖拦截次数。
- 单条内容模型调用次数、实际生成字段数。
- 每阶段耗时、等待耗时、Bundle 次数、缓存命中率。
- 单条内容人工点击次数、从选题到本地交付总时长。
- 模板复用率、首次质检通过率、单模板重试率。
- 历史阶段回访率、返修率、版本错配拦截数。
- 已批准文件与发布文件一致性校验通过率，目标 100%。

## 10. 视觉与交互规范

- 主要操作每屏只保留一个高优先级按钮。
- 长标题最多两行，生产内容优先于标题和状态说明。
- 正文和表单文字不小于 13px；辅助文字不小于 11px。
- 高级功能默认折叠：其他平台文稿、克隆样本、模板 Props、技术日志。
- 所有禁用按钮都解释原因；所有失败都给出下一步。
- 模板选择必须有真实预览，不用颜色块冒充模板效果。
- 页面切换和刷新保留未保存提示，不静默丢弃用户编辑。

## 11. 旧数据迁移与兼容

- 每个旧视频任务迁移为一个默认 Variant，指向当前已批准文件；旧审批不得复制到后续新生成的其他模板。
- 旧音频与 SRT 没有明确配对证据时标记为 `legacy_unpaired`，用户确认配对后才允许进入新渲染。
- 旧发布记录保持原样，不回写、不猜测其模板或版本关系。
- 历史阶段没有完整快照的旧任务只标记“当前版本”，不得伪造为“当时版本”；迁移后产生的新 revision 才支持完整历史。
- 迁移脚本必须支持重复执行、备份、完整性检查和回滚验证，不能直接改写旧发布证据。

## 12. 分阶段实施建议

### P0：正确性、版本与历史可查

- 建立 `Video Variant + file_sha256`，拆分文件级质检、审批和发布。
- 音频字幕显式配对，完成旧数据迁移与回滚验证。
- 建立 `stage_revisions`，实现历史阶段只读回看、URL 定位和返修确认。
- 文稿字段增加 revision/CAS 与候选版本，解决 AI 返回覆盖新编辑的问题。
- 移除 `updated_at` 导致的阶段整体重挂载。

### P1：按需文稿与 Skills

- 字段级来源、空缺检测和只补空缺。
- 母稿可选，当前平台口播稿作为唯一必要文稿。
- 写作 Agent Skills 配置、只读注入、能力检查和调用记录。
- 验证 CLI 模型路由能力；不支持时明确降级，不伪造配置生效。

### P2：Agent 编排、自动流水线与渲染提速

- 建立 `VideoBrief → 视频生成 Agent → VideoPackage → 审核路由 → 发布 Agent` 顶层契约。
- 复用现有 JobStore，实现进度、取消、刷新恢复和失败重试；进度同步到任务详情、任务列表和“今天”。
- 落地三级配置与配置快照，正在执行的 Job 不受后续默认配置修改影响。
- 动态素材 URL 与模板 Bundle 分离，按代码哈希复用 Bundle 和 `renderMedia()`。
- 增加 2 秒与 90 秒基准、真实耗时和缓存指标。
- 多版本结果卡、追加模板和单模板重试。
- 建立发布目标队列与右侧编辑器，落地 Platform Publish Adapter、平台元数据、封面管理、本地预览和同步为草稿/一键发布。
- 本地预览与实际同步共用 `payload_hash`，发布结果回写平台链接或明确错误。

### P3：后续增强，不阻塞首版

- 常驻 Node 渲染服务、全部下载 ZIP、完整性能诊断页。
- 视频链接自动下载、抽帧与结构分析。
- 更多模板、模板真实预览和制作方案预设。

## 13. 总体验收场景

1. 用户只手填抖音稿，没有母稿，可直接生成音频并完成视频。
2. 用户手填两栏后点击批量生成，系统只补空缺，手填内容完全不变。
3. 全部字段为空时，系统只生成当前平台所需文稿，不生成公众号文章。
4. 每次 AI 生成和改写均真实加载配置的去 AI 味儿与写作技巧 Skills，并可查看版本记录。
5. 进入成片后仍可回看脚本、录音、字幕和模板参数，历史内容默认只读。
6. 两种模板分别审批后，发布的确是各自选中的文件，不是最新 MP4。
7. 更换音频后，旧字幕被标记为不匹配，不能直接进入渲染。
8. 相同输入第二次生产不重复调用写作 Agent，也不重复 Bundle 或渲染。
9. 长任务刷新后仍显示真实进度，单个失败模板可以独立重试。
10. 追加一种风格时只新增渲染，不重新生成文稿、音频和 SRT。
11. AI 生成期间用户再次编辑同一栏，AI 结果只成为候选，不覆盖新编辑。
12. 两个任务复用同一 Bundle 时读取各自动态媒体 URL，不串用音频、字幕或图片。
13. 审批后替换文件内容，发布前哈希校验必须失败并阻止发布。
14. 旧任务迁移后可看到默认 Variant 和旧发布记录；无快照历史明确标为“当前版本”，不伪造历史。
15. 选题 Agent 与人工输入生成同一 `VideoBrief`，视频生成 Agent 输出包含明确 Variant 的 `VideoPackage`。
16. `review_mode=none + publish_mode=local_only` 可跳过内容审核并仅保存本地，但仍执行机器技术检查，不触发公开发布。
17. `review_mode=none + publish_mode=manual` 可不经过内容审核，但发布 Agent 仍要求用户确认具体文件和平台。
18. 审核 Agent 退回返修时携带具体 Variant 和证据；超过自动返修上限后转人工，不无限循环。
19. 发布中心可一次选择多个发布目标并在右侧逐个编辑，不再通过下拉菜单切换任务。
20. 批量套用元数据时保留目标平台已手工修改的封面、描述和标签；缺封面只阻塞对应目标。
21. 本地预览与实际同步使用同一 `payload_hash`，预览后修改字段会同步更新预览和发布参数。
22. “同步为草稿”只保存平台草稿，不记为已发布；“一键发布”必须返回平台链接才标记 `published`。
23. 发布结果不明时进入 `requires_review`，不得自动重发；单个平台失败不影响其他目标继续执行。

## 14. 本版默认决策

- 默认采用混合文稿模式：接受手填，也允许 AI 补齐。
- 默认只生成当前平台文稿，母稿和其他平台版本可选。
- 默认本地全自动生成草稿，审核 Agent 检查，结果仅保存本地；公开发布需另行选择人工确认或显式配置策略自动发布。
- 默认使用速度优先模型做普通草稿，重要内容可手工切换质量优先。
- 默认模板方案可配置，但不强制用户每次重新设置。
- 本期优先保证正确性、可操作性和可测性能，不以模板数量作为验收目标。

## 15. 最终自检结果

### 15.1 覆盖性检查

- Agent 关系完整：选题 Agent/中心、视频生成 Agent、审核 Agent、发布 Agent/中心职责明确。
- 输入与生产完整：多来源、手填/AI 混合、配音字幕、模板、多版本和本地输出均有对应功能。
- 历史与并发完整：`stage_revisions`、字段 CAS、候选版本和旧数据迁移均有约束。
- 发布完整：发布目标队列、批量编辑、平台元数据、封面、预览、同步、失败恢复和发布证据均有对应功能。
- 性能完整：按需生成、队列、缓存、Bundle 复用、动态素材隔离和 2 秒/90 秒基准均已定义。
- 原型完整：F01–F15 均包含桌面端线框与功能细节。

### 15.2 一致性检查

- 母稿可选与全空生成不冲突：全空时只生成当前平台所需文稿。
- 审核与发布不冲突：可不审核，但机器技术检查仍保留；自动公开发布必须显式配置。
- 本地预览与发布不冲突：必须消费同一 `payload_hash`。
- 同步与已发布不冲突：草稿同步不是发布，只有平台链接才能证明 `published`。
- 多模板与审批不冲突：每个 Variant 独立质检、审批、发布并校验文件哈希。
- 历史只读与返修不冲突：返修生成新 revision，不修改或删除旧版本。

### 15.3 开发前必须验证的外部约束

- 各平台真实发布地址、字段限制、封面规格、草稿能力和成功证据需通过实际页面验证并写入对应 Adapter。
- 自动发布受平台登录、验证码、二次验证和风控影响，不能仅凭本地预览承诺所有平台均可无人值守发布。
- 模型路由以当前 CLI 实际支持为准；不支持时按 PRD 明示降级。
- 视频链接深度分析、常驻 Node 服务和 ZIP 下载不进入首版关键路径。

### 15.4 自检结论

本 PRD 已形成“选题/人工输入 → 视频生成 → 审核路由 → 发布预览与同步 → 发布证据”的闭环，可作为开发拆解依据。后续变更需同步更新对应原型、数据约束和验收场景，不能只改界面描述。
