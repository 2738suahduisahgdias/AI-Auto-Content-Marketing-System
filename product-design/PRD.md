# 多 Agent 内容营销系统 PRD

**产品暂名：刘量内容增长工作台**  
**版本：PRD v1.0 / 待用户确认**  
**配套 Demo：`product-design/demo/index.html`**  
**本阶段边界：只做产品设计与交互确认，不改正式系统、不迁移数据库、不接入真实生成或发布。**

---

## 1. 背景与本次纠偏

现有系统已经具备本地任务、选题快照、五版脚本、录音字幕、素材授权、Remotion/FFmpeg、发布记录和复盘等雏形，也已有可复用的版本、资产和持久任务能力。

上一轮直接把技术重构结果替换成新首页，产生三个产品问题：

1. 把“文章”和“视频”拆成孤立工作台，破坏了一个选题连续生产多种内容的习惯。
2. 只展示技术对象和状态，没有围绕每天该做什么、Agent 正在做什么、下一步如何处理来组织页面。
3. 为控制改造范围而缩减了上传/混合渲染等已有能力，造成产品倒退。

本产品方案不再以技术模块作为信息架构，而以用户的**内容项目、每日工作和增长闭环**为中心。PRD 与 Demo 先确认，确认前不实施。

## 2. 产品定位

一套运行在本机的多 Agent 内容营销系统：从热点、收藏和账号数据中发现机会，经用户确认后，自动完成选题、文章、口播、配音字幕、素材规划、Remotion 视频、质检、发布与数据复盘，并把结果反哺下一轮选题。

**一句话价值：用户负责方向、判断和最终风险，Agent 负责研究、生产、执行和整理证据。**

### 2.1 目标用户

首要用户是刘量本人，而不是抽象的企业团队。系统首先服务一个高频内容创作者的一天，再考虑多人协作。

内容方向：

- AI 企业落地应用
- 普通人的 AI 教学
- AI 营销获客
- 个人思考和情感

目标受众：企业主、AI 从业者、希望进入企业 AI 落地的 FDE。

### 2.2 用户核心痛点

1. 知道 AI 有用，但不知道哪些业务场景值得做、如何开始、如何验收。
2. 不知道应该自己使用工具、找服务商，还是搭建团队。
3. 试过 AI，但结果不稳定，无法进入持续工作流程。
4. 企业主担心预算、数据安全、员工采用和项目没有实际回报。
5. 从业者和 FDE 缺少真实任务、完整项目证据和可复用作品集。

对创作者本人，另有四个生产痛点：选题耗时、跨平台改编重复、视频制作繁琐、发布后数据无法反哺内容。

## 3. 产品目标与非目标

### 3.1 目标

- 每周稳定生产 3–5 条短视频，并同步沉淀公众号文章。
- 普通视频 3 分钟以内，攻略型内容可独立做长视频/长文。
- 每个候选选题都可追溯来源、日期、证据和推荐理由。
- 一个内容项目可生成多个平台产物，但每个产物独立编辑、审核、发布和复盘。
- Agent 执行可查看、可暂停、可重试、可恢复；失败必须说明哪里错了、如何继续。
- 自动化能力分级开放，不以“已连接”冒充“端到端完成”。

### 3.2 非目标

- 不做通用聊天机器人、Agent 头像墙或通用 DAG 编排平台。
- 不承诺所有平台都能无验证自动发布。
- 不通过爬虫绕过验证码、风控、DRM 或平台限制。
- 不把收藏量、单条爆款或模型推断包装成稳定营销规律。
- 不为了“全自动”取消内容、版权、声音和发布的人工确认。

## 4. 核心产品原则

1. **一个主题，一个内容项目。** 文章和各平台视频是项目产物，共享研究与 brief，但不互相阻塞。
2. **每天先给下一步。** 首页不是数据库列表，而是今日优先事项、Agent 进度和待处理风险。
3. **Agent 以功能命名。** 用户看到“选题策划Agent”“Remotion视频Agent”，而不是技术代号。
4. **自动与人工边界可见。** 每个节点明确“自动完成、人工确认、仅记录、未接入”。
5. **证据与版本不可丢。** 人工修改生成新版本，旧发布仍指向旧版本，失效不等于删除。
6. **任何失败都允许继续。** 可跳过非关键项、改用上传、手工完成或只发布文章，不被一个节点卡死。
7. **模拟就是模拟。** Demo、测试数据、真实连接、真实发布和真实指标必须明确区分。

## 5. 核心对象与关系

### 5.1 内容项目 Content Project

用户日常操作的中心对象，包含：

- 主题、目标受众、核心痛点、内容角度
- 研究证据、收藏/热点/竞品来源
- 共享 brief、品牌语气、禁用表达
- 文章与视频产物列表
- 总体下一步，而不是一个强行统一的状态

### 5.2 内容产物 Content Output

一个内容类型 × 一个平台，例如：

- 公众号文章
- 抖音短视频
- 视频号短视频
- 小红书口播/笔记

每个产物独立拥有稿件、版本、素材、审批、发布链接和指标。母稿可以共享，但不要求所有平台版本同时生成或同时完成。

### 5.3 Agent 任务 Job

Agent 的一次可执行工作，如“分析 10 条收藏”“生成文章大纲”“渲染抖音视频”。必须具有真实状态、阶段、输入、输出、错误、耗时和重试记录。

### 5.4 素材与证据 Asset / Evidence

素材包括上传文件、录屏、合法素材库、AI 图片/视频、文章插图和封面。证据包括来源 URL、收藏条目、字幕区间、关键帧、账号指标和用户确认。

## 6. 多 Agent 分工

| Agent | 主要工作 | 输入 | 输出 | 默认人工边界 |
|---|---|---|---|---|
| 热点情报Agent | 汇总抖音热榜、收藏、竞品和账号数据 | 已授权浏览器/快照 | 带来源日期的情报池 | 用户确认采集范围 |
| 选题策划Agent | 去重、聚类、评分、提出差异化角度 | 情报池、账号定位、历史反馈 | 候选选题与证据 | 用户选择题 |
| 文章创作Agent | 大纲、正文、引用、摘要和平台排版 | brief、证据、文章要求 | 公众号文章版本 | 正文终审 |
| 口播编剧Agent | 母稿及各平台独立口播 | brief、平台 profile | 口播稿 | 口播确认 |
| 分镜导演Agent | 把口播和字幕转为时间轴与镜头 | 口播、SRT、时长 | 分镜与补卡建议 | 分镜确认 |
| 素材管家Agent | 上传、检索、授权、标签和素材匹配 | 素材库、分镜 | 可用素材清单 | 商用授权确认 |
| 配音字幕Agent | 真人录音、系统 TTS、本人克隆、ASR、SRT 校对 | 当前口播、音色、音频 | 明确配对的音频与字幕 | 声音授权与字幕确认 |
| Remotion视频Agent | 全模板、全上传、混合渲染与平台导出 | 冻结 manifest、素材、模板 | 可播放 MP4 | 用户选择模式 |
| 合规质检Agent | 规格、黑帧、静音、字幕越界、版权清单 | 成片与输入 manifest | 自动检查结果与返修点 | 人工最终审核 |
| 发布助手Agent | 发布前检查、定时、平台执行或引导 | 已批准产物 | 真实发布回执/URL | 首次与高风险发布确认 |
| 数据复盘Agent | 四窗口采集、对比、结论与选题反馈 | 发布记录、真实指标 | 复盘和下一轮建议 | 用户确认结论 |
| 流程监督Agent | 调度、重试、提醒、阻塞处理 | 所有任务与状态 | 今日下一步、异常通知 | 不代替内容审批 |

**Remotion、FFmpeg、FFprobe 是确定性工具能力，不伪装成语言模型。**

## 7. 端到端工作流

### 7.1 日常主流程

```text
热点/收藏/账号情报
  → 选题策划Agent 推荐
  → 用户确认主题与产物
  → 共享 brief
  ├─ 文章创作Agent → 引用检查 → 人工终审 → 导出 → 发布
  └─ 口播编剧Agent → 配音字幕Agent → 分镜/素材
       → Remotion视频Agent → 自动质检 → 人工终审 → 发布
  → 数据复盘Agent 回收 2h/1d/3d/7d
  → 下一轮选题推荐
```

文章与视频可以并行。视频返修不阻塞文章，公众号未发布不阻塞抖音复盘。

### 7.2 自动选题

1. 每日在用户授权的会话中读取热榜、收藏元数据和近期账号表现。
2. 去重并按内容方向、受众、证据、时效、差异化和制作成本评分。
3. 每个推荐显示“为什么推荐、来源是什么、哪些事实待核实”。
4. 用户可采纳、拒绝、换角度；反馈进入后续推荐。
5. 无新证据时不为了日更强行生成选题。

### 7.3 自动写文章

1. 从项目 brief 生成大纲，用户可编辑或接受。
2. 按大纲生成正文，支持章节级重写，不全文覆盖。
3. 事实性断言关联证据；无证据标为待核实。
4. 自动检查空标题、引用、链接、重复、排版和敏感内容。
5. 人工终审后导出 Markdown、安全 HTML 和素材包。
6. 公众号自动排版/发布作为独立连接器验收，未完成时提供复制与人工发布引导。

### 7.4 自动制作视频

1. 当前平台口播独立生成，可只做抖音或同时创建多个平台产物。
2. 用户选择真人录音、系统音色或本人授权克隆；默认推荐上次音色。
3. 音频与 SRT 显式配对，字幕编辑产生新版本，禁止跨版本混用。
4. 分镜导演Agent生成时间轴，素材管家Agent提供已有素材、录屏计划、搜索词和 AI 生成提示词。
5. 用户选择三种构建方式：
   - **全 Remotion**：文字卡、图形、字幕、B-roll、模板动画。
   - **全上传**：已有视频/图片 + 口播 + 字幕。
   - **混合**：上传镜头与 Remotion 模板混合，缺失镜头明确补卡。
6. 预览时间轴、素材来源和版本后再渲染。
7. 自动检查画幅、时长、音轨、黑帧、静音、字幕与版权项；人工看成片终审。

### 7.5 发布

采用分级自动化，而不是一次性承诺所有平台全自动：

- **L0 仅记录**：人工发布，系统保存真实 URL。
- **L1 发布辅助**：自动填充标题、正文、标签和素材，用户最终点击发布。
- **L2 定时自动发布**：已批准产物按计划在已授权会话执行；异常暂停并请求用户处理。
- **L3 策略自动化**：根据规则选择时间和产物，仍需总体开关、预算与平台限制。

每个平台独立验收和启用。扫码、验证码、滑块和二次验证由用户处理，不能无限重试。

### 7.6 自动分析

- 发布后按 2h、1d、3d、7d 创建采集任务。
- 保存实际采集时间；错过窗口标“逾期/缺失”，不伪造历史值。
- 指标包含播放/阅读、点赞、评论、分享、收藏、涨粉、主页访问和有效咨询，按平台可用性读取。
- 同平台、相近发布时间比较，不直接比较跨平台绝对数。
- 复盘输出“事实、推断、下次实验”，并将采纳/拒绝反馈给选题策划Agent。

## 8. 信息架构与页面要求

一级导航保留并扩展旧版习惯：

1. **今天**
2. **选题中心**
3. **内容项目**
4. **研究与素材**
5. **发布与复盘**
6. **Agent任务**
7. **设置**

“文章”和“视频”不再作为两个孤立一级工作台，而是内容项目内的产物视图。

### 8.1 今天

- 今日建议、待审核、阻塞、定时发布和运行中 Agent。
- 本周发布目标与有效咨询，不只显示播放。
- 一张“继续当前项目”主卡，直接到下一步。
- Agent 正在执行的任务可展开查看阶段，不展示技术 lease/token。

### 8.2 选题中心

- 热榜、收藏、竞品、账号表现、历史推荐五个来源筛选。
- 候选卡片包含评分理由、证据、受众、推荐形式和预计成本。
- 支持创建“文章”“视频”“两者”。
- 详情抽屉展示来源与相似历史内容，避免重复题。

### 8.3 内容项目

- 列表按最近活动、待审核、阻塞和发布计划筛选。
- 项目顶部：主题、受众、共享 brief、产物和下一步。
- 项目内 Tab：总览、文章、视频、证据与版本。
- 视频工作室包含口播、音频字幕、分镜时间轴、Remotion 预览、渲染设置和版本。
- 文章工作室包含大纲、正文、引用、排版预览、版本差异和导出。

### 8.4 研究与素材

- 研究库与生产素材库分区，研究可看不等于可商用。
- 收藏条目只在点击分析时下载和处理。
- 素材支持上传、标签、搜索、授权范围、关联项目和源片段。
- AI 素材显示模型、提示词、费用和生成记录。

### 8.5 发布与复盘

- 日历/列表展示待发布、已发布和采集计划。
- 每个平台显示真实连接状态与自动化级别。
- 数据卡同时展示内容表现和有效咨询，缺失不显示 0。
- 复盘结论可一键转为下一轮候选题，但仍需用户确认。

### 8.6 Agent任务

- 按运行中、待处理、已完成、失败筛选。
- 展示功能名、项目、真实阶段、耗时、费用和输出。
- 支持取消、重试、跳过失敗可选步骤、改手工完成。
- 错误包含项目/节点/文件、原因、修复动作和追踪 ID。

### 8.7 设置

分为四组，避免一张技术长页：

- 账号与平台连接
- Agent 与自动化级别
- 模型、语音与本地环境
- 数据、隐私、预算和备份

## 9. 状态、版本与异常体验

### 9.1 状态表达

用户看到“待选题确认、文章待终审、视频渲染中、待发布、待复盘”等业务状态；技术 job 状态只在 Agent 任务页展示。

### 9.2 版本规则

- 每次人工编辑和 AI 重写都生成新版本。
- 审批绑定当前输入，修改后明确哪些下游需要重做。
- 活动音频、字幕、分镜和渲染可查看、可切换、可比较。
- 已发布版本不被新草稿覆盖。

### 9.3 阻塞恢复

- 登录失效：打开连接窗口，处理后续扫。
- 模型失败：换允许的同能力模型、重试或手工编辑。
- 素材失败：换素材、Remotion 补卡或跳过该镜头。
- 渲染失败：保留旧成片，显示失败阶段和命令摘要。
- 发布失败：不重复提交，先核对平台是否已成功。
- 磁盘/外置盘不可用：暂停重任务，不创建空目录冒充原数据。

## 10. 成功指标

### 10.1 产品指标

- 每周完成发布的文章/视频数量
- 从选题到首次发布的中位耗时
- 人工返修次数与最常见返修节点
- Agent 成功率、恢复成功率和平均执行成本
- 候选题采纳率、重复主题率、证据覆盖率

### 10.2 内容指标

- 目标用户互动、收藏、分享、主页访问和有效咨询
- 各平台四窗口真实表现
- 企业落地/培训相关咨询数量与质量
- 不把“生成数量”“Agent 数量”当增长成果

## 11. 非功能要求

- 本机优先，媒体与研究数据可控制是否发送云端。
- 主服务异常不丢任务，刷新和重启可恢复。
- 长任务后台执行，页面可关闭。
- 普通桌面页面清晰、克制、编辑优先；支持 1440px 为主，1024px 可用，手机以审核为主。
- 所有危险操作说明后果；可逆保存不反复弹窗。
- 不输出 API Key、Token、Cookie 或敏感配置。

## 12. 旧版结构与模块增删安排

### 12.1 产品结构

| 旧结构 | 处理 | 新安排 |
|---|---|---|
| 今天 | **保留并增强** | 加 Agent 进度、阻塞、发布计划和有效咨询 |
| 选题 | **保留并增强** | 合并热榜、收藏、竞品、账号反馈与证据 |
| 任务 | **保留但改为内容项目** | 一个主题下管理文章和各平台视频 |
| 账号 | **拆分复用** | 连接管理进设置；内容与指标进发布与复盘 |
| 设置 | **保留并分组** | 平台、Agent、模型、隐私预算四组 |
| v2 文章页 | **不作为一级导航保留** | 编辑能力并入内容项目/文章工作室 |
| v2 视频页 | **不作为一级导航保留** | 媒体能力并入内容项目/视频工作室 |
| v2 任务队列 | **保留并产品化** | 改为 Agent任务，隐藏技术细节 |
| 旧版只读 | **保留** | 历史入口，不再作为工作路径 |

### 12.2 技术底层复用

| 已有能力 | 决策 |
|---|---|

## 13. 验收标准

### 13.1 产品闭环

- 能从真实情报生成候选题，并查看来源和推荐理由。
- 一个项目可只做文章、只做视频或两者，互相不阻塞。
- 文章自动生成、编辑、审核、导出和发布可完成。
- 三种视频模式均可生成真实可播放 MP4，混合缺镜头有明确补卡。
- 已批准产物能按平台自动化级别发布或引导发布，并取得真实 URL。
- 四窗口数据来自真实记录，复盘建议能返回选题中心。

### 13.2 可靠性

- 音字版本混搭被阻止，字幕编辑保留来源。
- 长任务刷新/重启不丢，失败不重复扣费或重复发布。
- 任一非关键素材失败都能换方式继续。
- 测试、模拟、连接成功和正式端到端完成有明确不同标签。

## 14. 确认后的实施顺序（不是本轮开发文档）

1. **产品壳与兼容层**：按本 PRD 重组导航和项目视图，保留现网数据与底层接口。
2. **自动选题与文章**：真实情报、证据、独立文章闭环。
3. **完整视频工作室**：恢复三模式、素材、配音字幕、分镜、预览和质检。
4. **平台发布**：逐平台完成 L0→L1→L2 验收。
5. **自动分析**：四窗口采集、复盘和选题反馈。
6. **全链路回归**：真实文章与视频各一条完整证据链，再开放更高自动化。
