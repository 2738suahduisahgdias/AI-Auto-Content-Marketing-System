目前可以继续评审与验证，但不能作为完整桌面产品交付。原系统底座仍在，映序以源码适配接入原视频任务，未用 iframe 代替功能迁移。主要缺口集中在 Agent 交接、桌面本地能力和设计一致性，不应再次推翻已有系统重建。

## 本轮已经修改并验证

- 设置拆成 Agent 配置、模型连接、本地媒体、视频模板、数据与自动化五个 URL 子页面。切页保留未保存 Agent 草稿，原保存、连接测试和模板接口保留。
- 删除社媒能力、内容复盘、竞对分析的主导航与路由，保留账号日报和原选题数据。旧功能源码和历史数据库没有清除；原选题中心的竞品收藏来源不在删除范围。
- 知识库新增本地 SQLite 增长记忆：新增、修改、搜索、分类、暂停/启用；区分有效经验、避坑记录和待验证。有效经验和避坑必须填写来源与效果依据；这是人工提供的依据，不冒充系统核验数据。
- 抖音、小红书、行业选题 Agent 读取适用平台最近 20 条启用记忆，保留真实来源输入，记录模型实际引用的有效 memory_ids 和记忆快照。虚构引用被过滤，停用记忆不再进入新推荐。已生成推荐保留当时证据。
- 原知识网络、采集知识库、发布知识库保留。同步知识网络不等于自动生成有效经验。记忆保存在本机；运行模型推荐时会发送相关文本上下文，界面明确提示。
- 发布页按接收交付、审批、字段预填、人工确认组织，沿用原接口，删除绕过逐项终审的列表批量发布快捷入口。预填与公开发布继续区分。
- 修复发布 preview_url / variant_id 与前端字段命名不一致，文章跳转 ID 未匹配而误选第一篇文章，来源接口报错被伪装为空列表等问题。
- 修复同一任务的多个成片共用最新发布批次/字段任务的问题。bootstrap 按 source_file_id 取批次，字段生成任务携带并过滤同一文件版本。
- 多行文本框统一允许横向和纵向拖拽，编辑区域可以滚动；单行框保持表单布局。修复时长框内边距挤掉数字、素材来源选框过窄。
- 账号日报的大面积绿色底、深绿色指标卡和头像改为暖白、琥珀与棕金体系。原指标与交互保持。
- 标记旧独立 demo 验收文档为历史材料，避免将已否决方案当作当前完成记录。

## 设计验收结论

保持用户选定的布局：项目工作台为整体，映序专业制作页负责视频；继续暖白底、琥珀主色、少量香槟金。此次不更换整体设计方案。对公众号日报、视频分镜、设置、记忆和发布页进行了浏览器检查。桌面常用宽度已查看；本轮没有完成每个页面的手机、键盘和屏幕阅读器全覆盖验证。

横向拖拽实测：分镜文本框由约 299×84 px 改为 374×112 px，正文未改变，时长字段数字可读。临时输入测试未保存到作品；临时记忆验收记录已从隔离库清除。

## 验证记录与边界

- 全量前端：26 个文件、44 个测试通过。原测试中竞对入口与批量直接发布的两条断言按新需求更新，未忽略失败。
- 后端重点回归：25 个测试通过，覆盖增长记忆、原映序迁移、发布批次和文件版本隔离；并非全仓库后端测试全量运行。
- TypeScript 检查通过；Vite 独立构建通过，输出 webapp/dist，没有覆盖原 web/react-dist。既有 eval 警告保留在待办。
- 浏览器验证本地记忆保存、刷新持久化、停用，设置跨页草稿，视频多行框双向拖拽，发布页布局与账号日报。
- 未进行真实社交平台预填/发布、收费模型调用、真实新爆款判断或桌面安装验收。

## 下一步建议顺序

1. 先补映序成片 → 原审核批次 → 发布 Agent 的一条真实交接闭环，这是当前最影响试用的阻塞。
2. 总工作台聚合全部 Agent 状态，发布页收敛为逐平台编辑，清晰显示执行器和依赖状态。
3. 原收藏与自己的作品一键沉淀记忆，效果快照提供证据，形成“推荐—制作—发布—记忆”的真实循环。
4. 文章配图、品牌规则质检与 AI 视频能力按原接口补齐。
5. Mac 打包、离线授权和大文件能力达到验收条件后，再合并原始代码和发给首批客户。
