# 映序 Mac 本地创作工作台开发与验收方案

版本：1.0。日期：2026 年 11 月 1 日。面向产品负责人、开发与测试。

本方案统一历史需求、最近确认的本地部署和离线授权方案，以及当前代码基线。目标是客户在自己的 Mac 上激活软件、完成基础配置，用“AI 客服如何落地”模板制作第一条真实视频并导出或发布，同时保留原有内容运营能力。本文件是开发规格，不代表所有能力已经完成。

## 1 已确认的产品边界

- 第一批客户使用 Mac；第一条示范内容为“AI 客服如何落地”，采用知识讲解和 Remotion 动态流程图。
- 项目、文案、视频、音乐、模板实例、任务与引导进度存本机。无云端内容存储、云端项目同步或云端渲染平台。
- 外部文字、配音、视频模型可以按需联网调用；必须明确该次发送的内容范围。本地部署不等于外部模型在本地运行。
- 首期采用微信联系加离线授权。取消手机号注册、短信验证码、云账号服务器及自动用户行为回传。
- 客户端继承完整创作工作台；经营者单独使用本地授权管理工具，登记客户并发码。
- 用户原文案、原素材和已有项目必须受保护。取消重复路径选择、反复勾选和与任务无关的强制设置。
- 开发在独立 Git 分支完成，验证通过后再合并主分支；不直接改主分支或正在运行的生产数据。

## 4 信息架构与 UI 方案

已确认：项目工作台作为整体，专业制作台作为视频编辑页，运营流水线作为看板视图。引导式创作保留为首次使用流程。视觉方向采用 Mac 的银灰窗口层次与专业创作面板组织，当前为待用户评审的视觉原型。三个视图共享同一套数据。

- 项目工作台：左侧全局导航，中间内容项目，右侧预览或助手。适合选题、文章、视频、发布日常协作。
- 引导式创作：顶部步骤，单页聚焦当前任务，默认值更充分。主要用于新手和快速生产。
- 专业制作台：分镜或素材列表、画面、属性面板、时间线。文案与镜头关联，适合混合素材和精细修改。首期不做完整通用剪辑软件。

批量运营看板作为“内容项目”的可切换视图保留，不能因本轮引导式方案而遗漏早期讨论的运营流水线。

全局导航：今日工作、灵感研究、内容项目、素材与方法、发布排期、数据与线索；底部为管理中心、系统设置、帮助与联系。经营者授权管理工具独立分发，客户应用不包含私钥及发码能力。

项目内部：简报、文案、视频制作、发布版本、复盘。简报属于项目，没有全局重复简报。模板选择提供用途和效果，技术路由作为自动默认或高级属性，不在输出规格中重复要求选择。

## 5 离线授权与首次使用

### 5.1 授权流程

客户首次启动生成安装标识与申请码，展示微信二维码；复制申请码发给经营者。经营者录入客户备注、微信备注、授权类型和期限，生成带数字签名的授权；客户粘贴或导入授权文件，本机验证成功后保存凭证。

建议 Ed25519 签名，协议载荷包含 schemaVersion、licenseId、productId、installationId、issuedAt、expiresAt（长期可空）、features、keyId。规范化编码后签名，限制载荷大小和字段类型；应用内置公钥，经营者私钥仅在独立工具内受保护。服务编号与授权编号不得使用真实手机号推导。具体安装标识方案在 macOS Keychain 原型验证后确定，不宣称可以绝对防复制。

授权状态：未激活、有效、到期、签名错误、安装不匹配、版本不支持。错误可读，允许重输，不清理项目。到期仍可访问已有产物和备份。试用期、正式期限、设备政策为可配置项，7 天和 1 台仅演示默认，不是已批准商业规则。

纯离线不能即时远程撤销、可靠统计活跃、严格限制同时设备数或完全抵御时钟回拨。换机重新申请与补发，旧机不会自动失效。记录上次可信运行时间只能降低明显回拨风险，不能伪称联网验证。

### 5.2 经营者工具

字段：本地客户 ID、称呼、微信备注、可选行业和需求、申请码、授权编号、类型、发放与到期时间、补发关系、内部跟进备注。状态使用“已发码”，不能无证据显示“已激活”。提供查找、生成、复制、导出授权文件、客户记录备份与恢复。

客户列表备份与签名私钥备份分离；私钥加密备份并验证恢复流程，明文不得进入代码仓库、普通日志、安装包或项目包。误丢私钥后的轮换需要发布带新公钥的客户端，设计 keyId 兼容旧授权。

### 5.3 首次与再次启动

保存 onboardingVersion、完成步骤、最近项目和必要偏好。首次激活后开始引导；中断后继续；已完成者进入最近项目或工作台；更换版本只提示新增必要配置。重新体验引导不清空文案或素材。

引导：选择本地目录 → 环境检查 → 当前模板所需能力 → 选择模板 → 输入或导入文案 → 短预览 → 真实渲染 → 导出或发布。

环境检查提供真实通过/失败/未检查，不用假进度。人工文案无需文本模型；不使用 AI 镜头就无需视频模型；无旁白不应强制配音密钥；没有发布账号仍可导出。

微信二维码使用用户提供原图，不重绘、不裁掉识别区域。激活、引导和帮助均可打开；支持放大查看。实际扫码由真机确认，浏览器显示成功不代表已扫码或已加好友。

## 6 创作与生产流程

### 6.1 灵感和文案

选题可以来源于平台收藏、搜索结果、竞对、拆解报告或手动输入。文案可以来自选题、AI、粘贴和文件导入。首期支持 UTF-8 TXT/Markdown；DOCX 作为后续适配，界面只显示真实可用格式。

自动保存与显式保存共存；保存失败不能显示成功。保留版本、来源和最后修改；AI 返回使用预期版本号，遇到手工新修改保存为候选，不覆盖。只生成需要的文案，不强制五版或母稿。

### 6.2 场景与制作路由

Remotion 场景：知识讲解、口播包装、科技概念、数据图表、流程说明、产品操作教程、时间线、案例对比和列表总结。
AI 视频场景：广告片、短剧、人物表演、电影感产品镜头、复杂实景运动。上传人物/物品图片加用户要求属于 image-to-video，返回真实视频后进入素材库。
上传实拍：允许作为完整片段使用，也可显式裁切；默认读取真实时长、分辨率、帧率和原声音轨。混合片可以同时含代码动画、AI 镜头与上传片段。

Scene 记录 content、sourceType、assetId、templateId/version、durationPolicy、in/out、originalAudio、generationPrompt。路由可按镜头覆盖；选择平台只改变输出参数与发布元数据。

### 6.3 时间与声音

时间线支持旁白驱动、音乐驱动、素材驱动。上传成片默认素材驱动；旁白长短与镜头冲突时提示选择延长画面、修改旁白或显式裁切，不静默截断。时长按帧计算并允许小量编码误差，验收比较真实媒体时长。

旁白、素材原声、配乐、音效为不同音轨。旁白可 AI、上传或无；音色样本在配音设置管理，不混入配乐。支持音量、淡入淡出、旁白期间配乐压低；音频修改更新字幕关联并提示受影响镜头。

### 6.4 音乐自动分析

用户选择本地音乐目录后扫描支持格式；不擅自扫描整台电脑。持久化时长、采样率、声道、响度/峰值、静音、估计 BPM、节拍点和能量段落。情绪与风格是可编辑推断，显示来源及不确定状态，不能当确定事实。

以文件指纹和分析器版本缓存结果；不变文件不重复分析。推荐参考场景、节奏、长度和用户偏好，允许试听、替换、手动校正。分析失败不伪造结果。网络音乐保留原链接和使用范围信息，浏览、导入与项目使用分别处理；首期先完成本地音乐库，网络来源逐项适配。

### 6.5 模板与效果库

模板包含适用场景、样例视频或真实预览、参数、提示词、依赖能力、模板和引擎版本。内容结构与视觉风格分离；参数包括配色、字体、动效强度、字幕和节奏。

首批效果候选：动态大字、科技 HUD、流程连线、数字增长、图表对比、纸张叙事、产品运镜。AI 提示词与 Remotion 参数分开，不将同一提示词当成通用模型参数。每个效果需有可看的样例；不把静态占位图称为视频效果。

项目保存模板快照；库更新不悄悄改变旧项目。保持最新基线的内容驱动 Storyboard 与预览共享产物机制。用户修改输入后预览失效提示清楚；避免为每次简单保存增加人为确认关卡。最终预览确认规则与最新上游规格差异在实现时集中处理。

### 6.6 渲染与发布

复用现有 Worker、JobStore、模板引擎和渲染服务，不建立第三套任务队列。任务有真实状态、进度、阶段耗时、取消、失败原因、重试和恢复；不能以定时器模拟成功。

预览与正式渲染共享内容、镜头、模板版本、素材和随机种子，只调整允许的编码质量。输出校验格式、视频流、时长、音轨和文件可读性；无旁白作品不强制音频存在。

发布以具体内容版本和成片指纹为单位，保留封面、标题、描述、标签和各平台差异。提供本地效果预览、可用的平台预览、保存草稿及发布。结果不明时先查询，不自动重复发帖。用户可只导出；平台能力不足时给出明确降级路径。

## 7 内嵌浏览器与内容拆解

Electron WebContentsView 承载平台真实页面，放在映序自己的框架内；不是通过 iframe 或删除远端安全头实现嵌入。自有工具栏属于应用，包含地址、返回、刷新、收藏、下载拆解和任务状态。

远端页面不启用 Node、不接触本地文件接口，隔离会话且 IPC 限制可信来源；HTTPS 导航校验、弹窗和下载交给受控路径。平台登录由用户完成，不自动处理验证码。平台仍可能限制自动化，不能承诺所有网页永久可采集。

下载拆解流程：记录来源 → 获取可访问媒体 → 本地存储 → 音频转写 → 场景检测/抽帧 → 音画对齐分析 → 保存报告 → 转选题、文案或效果模板。报告字段包括时间码、转写文本、画面内容、镜头手法、动效、声音节奏及可复用建议。不可获得媒体时保留链接，支持用户导入已下载文件。

同一来源去重，任务可取消和重试；不得将“收藏链接”显示为“已下载”。获客需求先复用最新社媒数据模块，把内容、作者和线索来源关联；自动私信、自动加好友不属于已确认范围。参考获客视频的详细字段须在转写和画面核对后补充，不能凭标题虚构。

## 8 后台配置

管理中心：Agent 与能力、运营平台账号、品牌规则。素材与方法：模板、提示词、音乐和音色。系统设置：服务连接、目录与缓存、依赖环境、诊断备份、授权信息。

Agent 配置包含职责、模型绑定、提示词/Skill 版本、知识来源、可用工具、输入输出约定、超时重试和成本限制。Agent 使用已有服务连接；渲染工具不要求再绑一个文本模型。配置必须在真实执行日志中可核对，不只存表单。

服务按文字/代码、视频、配音、转写、音乐分析分类。视频提供商独立配置模型、支持比例时长、图片参考、任务查询、取消与计费提示；失败不自动切换到付费服务。

平台账号保存本地登录状态，区分未登录、可用、过期、未知与能力不支持。微信平台运营登录与“联系刘洋”二维码没有绑定关系。API Key、Cookie 等不进入普通日志、备份包或源码。

## 9 本地技术架构与数据约定

建议 Electron 管理窗口与本地进程；React 继承原工作台；Python 提供本地 API、SQLite 与 Worker；Node/Remotion 和 FFmpeg 执行媒体处理。架构应先与最新仓库启动方式核对再定实施细节。

本地 API 仅绑定回环地址，使用随机会话凭证、可信来源校验和受限 IPC；网页 iframe 或平台页不能访问服务。启动有端口冲突处理、健康检查与失败诊断，退出处理子进程与进行中任务。并发按实测硬件能力设置，不无条件全核抢占。

建议实体映射而非全部重建：Project/ContentItem、Revision、Scene、Asset、AudioAnalysis、TemplateVersion、Job、RenderArtifact、Publication、OnboardingState、License。已有任务 ID、文件 ID 和版本 ID 保留映射；字段包含 schemaVersion、expectedVersion、输入指纹和依赖关系。

目录分离应用数据、数据库、项目、托管素材、引用素材、可再生缓存、成片、备份和日志。媒体用文件而非大 Blob 入数据库。路径不暴露在远端服务的非必要参数中；诊断包默认脱敏。

操作契约至少覆盖授权请求/安装、引导读取保存、目录选择、素材探测引用/复制、缺失重连、音乐扫描分析、预览/渲染/取消/重试、项目打包恢复。具体 API 路径复用现有接口风格并在实现提交中补充，不为规划路径误改当前生产端点。

## 10 五项大文件管理要求

1. 默认引用原文件，可选复制。引用/托管状态可见；复制写临时文件，完成校验后提交。移除引用不删除原片；重复导入可复用。文件变化使相关缓存失效。
2. 外置盘支持卷标识和相对路径。断盘标记离线，暂停依赖任务；重新连接检查恢复；支持选择新根目录批量重连。不能只凭同名匹配错误素材。
3. 低清代理用于预览，原片用于最终输出。缓存目录与上限可配置，展示可回收空间；仅删除登记的可再生产物，保护原片、成片、数据库和正在使用的缓存。不能把缓存清理写成任意目录递归删除。
4. 分别检查输出盘、缓存盘和临时盘空间；预估编码与临时占用并保留余量。磁盘写满或断盘保留可恢复状态；复用通过校验的阶段产物。不能续跑的编码阶段重做，不承诺任意帧断点续渲染。
5. 轻量备份保存项目和引用清单；完整备份包含全部必要媒体、模板版本和依赖清单。大项目支持目录式包，不强制把全部内容塞进内存。导入校验清单、路径穿越、校验和、缺失字体和版本兼容；不覆盖同名项目。默认排除密钥、Cookie、私钥和机器激活凭证。

## 11 删除与迁移清单

取消重复全局简报、重复制作路由、强制五版稿和逐项质检打勾通关；新版本已简化的部分不重复实现。移除模糊声音入口，将音色、旁白、音乐分开。

合并文章/视频一级入口为内容项目，保留类型视图；合并审核与发布导航，但保留外部文件批量检查能力；汇总账号日报、复盘、竞对入口但不删除功能；向导收进设置，首次自动出现。

旧版入口、重复页面和 demo 分支只有在确认无业务依赖后才删除；先完成新旧 ID、版本、素材及发布关联迁移。/api/tasks 不因名字“旧”就删除；上游新生产代码仍依赖它。独立 demo JSON 不直接假装兼容旧项目导入。

迁移先备份数据库与文件清单，使用副本执行，记录迁移版本与校验结果。至少迁移一份真实旧项目并渲染，比较文案、素材关联、历史成片和发布记录。失败回滚数据库和应用版本，不删除媒体。

## 13 测试矩阵与验收证据

- UI：三个布局、各步前进回退、键盘焦点、二维码开关、输入错误、空文案、刷新恢复、返回不丢配置、导出后文件有效。检查 Mac 常用窗口尺寸及窄窗口，不溢出或挡住按钮。QA 使用隔离数据，不留测试客户干扰体验。
- 授权：正确签名、篡改、错误设备、到期、格式损坏、超长输入、重复导入、时钟异常、私钥备份恢复。客户包中检索不到签名私钥和发码实现。
- 第一条视频：真实输入、真实字幕与音频、四个语义镜头、短预览和正式片视觉一致、导出流与时长验证、人工播放检查。原片时长与混合轨道另设用例。
- 任务：重复点击不重复扣费/渲染；取消后不误记成功；中断重启可恢复；输入版本变化不复用过期预览；失败保留可重试信息。
- 存储：大文件引用不复制、复制中断、断盘/换盘符、重名文件、空间不足、缓存清理保护原文件、完整包在另一设备恢复、无密钥泄露。
- 浏览器：平台页不能调用本地特权 IPC；无效地址提示；登录过期；下载与收藏状态区分；转写和关键帧的时间码对齐。
- 发布：先验证草稿与预览，不以测试名义未经授权公开发布；确认已授权的发布测试目标后核实真实平台结果。结果不明不重复发送。
- 回归：原文章、选题、账号、知识库、审核、发布、数据与最新新增模块均有烟测。按变更选择仓库现有测试及构建检查，记录命令、commit、结果与失败项。
- Mac 发行：Apple Silicon 与 Intel 支持范围、最低 macOS 和内存需求待设备实测确定；正式交付需评估 Developer ID 签名、公证、更新签名、依赖分发及许可。当前 x64 原型不代表两个架构都已验收。

测试报告必须区分静态检查、DOM 模拟、真实浏览器点击、真实媒体渲染、打包安装五种证据。单一 node --check 或截图不能证明全链路通过。不得把待接入按钮的提示弹窗视为真实生产功能验收。

## 14 分支保护与合并流程

只在 codex/yingxu-mac-local-workbench 开发。主分支在隔离 checkout 外保持不变；每次实施先检查工作区和远端基线。

按文档、UI、授权、媒体、迁移拆分可审阅提交；敏感资料、真实客户数据、媒体大文件、node_modules 和构建垃圾不得提交。用户微信二维码目前仅本地演示使用，不随文档提交到公开仓库。

发现主分支新提交时先同步并重新检查差异，不用旧分支覆盖新工作。提交前检查 diff 和相关测试；最终开 PR 附真实验收证据、数据迁移及回滚说明。只有开发完整、必要测试通过且无未解决发布阻塞项，才按用户授权合并；本轮只提交文档，不合并或部署。
