# 微信随手记与后台分类 PRD / 技术方案

状态：待产品确认后开发  
对应菜单：选题 → 视频号选题  
专用通道：视频号选题收集 Agent

## 1. 背景与最新决策

用户在微信中发现好视频、好文章或产生想法时，需要低打扰地记录到内容增长平台。

最新决策取代此前的“微信中用 #标签 分类”方案：

- 微信私聊不要求分类、不要求记忆命令。
- 微信只负责发送链接、内容或备注，备注用于记录当时的想法。
- 分类、标题修改、备注修改、归档和转生产任务全部在后台完成。
- 后台修改是主数据，不与微信聊天记录做双向同步。

## 2. 目标

1. 用户可以在微信私聊中随手发送内容，无需按照固定格式输入。
2. 所有成功接收的内容进入后台“待分类”。
3. 用户可以在后台集中分类和编辑，随后转为真实内容任务。
4. 同一视频允许在不同时间重复记录不同想法，消息不能互相覆盖。
5. 保存结果必须真实可验证，微信收到成功回执才表示已入库。

## 3. 非目标

- 不在微信里自动判断精选、竞品、高赞或行业分类。
- 不自动下载、拆解或发布收到的视频。
- 不把聊天内容当作可执行指令，不开放 Shell、浏览器或发布权限。
- 不支持微信群聊；当前只设计私聊。
- 不把电脑或服务离线期间的消息宣称为已保存。
- 不承诺所有视频号、抖音分享卡片都能提取出公开链接，必须通过真实消息测试。

## 4. 用户角色与核心流程

### 4.1 微信随手记录

用户可以发送：

```text
https://内容链接 这个开头很好，后面可以做成案例
```

也可以只发送：

```text
以后可以讲一期：企业AI项目为什么试点后扩不了量
```

或者转发支持的视频、文章和卡片。

系统行为：

1. 原样保存消息，不要求标签或固定顺序。
2. 能提取链接时保存为原始链接；提取不到时保留原始消息和附件元数据，不伪造链接。
3. 默认进入“待分类”。
4. 保存成功后微信回复简短回执；失败时返回真实失败原因。

### 4.2 后台集中整理

用户进入“视频号选题”，默认看到“待分类”：

- 修改标题。
- 修改或补充想法备注。
- 选择精选、竞品、高赞、行业分类。
- 打开原始链接或查看原始消息。
- 归档不感兴趣的内容。
- 将整理后的条目转为真实内容任务。

分类后可再次修改，不新增重复条目。

## 5. 功能需求

### P0：后台待分类与编辑

1. 新增“待分类”视图，并保留精选、竞品、高赞、行业和已归档。
2. 列表展示标题、原始链接、想法备注、消息类型、接收时间和分类状态。
3. 详情抽屉支持编辑标题、分类和备注。
4. 保存后刷新当前列表并明确提示成功或失败。
5. 原始消息只读，用户编辑字段与原始字段分开保存。
6. 手动录入与微信入库共用同一套编辑和分类能力。

### P0：微信私聊入库

1. 使用腾讯维护的 `@tencent-weixin/openclaw-weixin` 插件。
2. 专用视频号选题收集 Agent 只调用本地选题接口。
3. 仅允许本人微信账号写入；其他发送者拒绝并记录安全事件。
4. 文本、链接和备注优先打通；媒体与分享卡片按真实测试结果逐项开放。
5. 成功回执包含保存结果，例如“已保存到待分类”。不包含 AI 自动分类结论。
6. 本地保存失败、接口超时或权限拒绝时不得回复成功。

### P0：去重与重复记录

- 同一个 `msgid` 重试只能入库一次。
- 同一个 URL 在不同时间、不同 `msgid` 下可以再次记录，保留不同想法。
- URL 用于关联相同内容，不作为消息唯一键。

### P1：批量整理与媒体增强

- 多选分类、批量归档。
- 相同原始链接的消息聚合计数。
- 图片、语音、文件和视频附件的本地保存与预览。
- 分享卡片结构化解析；解析失败时保留原始数据并提示补充链接。

## 6. 后台信息架构

分类顺序：

1. 待分类（默认）
2. 精选
3. 竞品
4. 高赞
5. 行业
6. 已归档

条目状态与内容状态分开：

- `connection_status`：微信通道连接状态。
- `ingest_status`：本条消息保存成功、失败或待补信息。
- `category`：unclassified、featured、competitor、high_praise、industry。
- `analysis_status`：未拆解、处理中、已拆解或失败。

“收到消息”不能自动变成“已拆解”，“保存成功”不能自动变成“已发布”。

## 7. 数据设计

新增 `wechat_topic_messages` 表，保留现有 `wb_research_items` 作为选题研究主表，避免重写现有工作流。

建议字段：

- `id`：本地消息 ID。
- `msgid`：微信消息 ID，唯一约束。
- `research_item_id`：关联现有研究条目。
- `sender_id`：发送者标识，仅用于权限校验，不在页面公开。
- `message_type`：text、link、image、voice、file、video、card、unknown。
- `raw_text`：原始文本，只读。
- `original_url`：实际提取到的链接，可为空。
- `raw_payload_json`：必要的原始元数据，不保存 Token、Cookie 或凭据。
- `title_override`：后台修改后的标题。
- `note_override`：后台修改后的想法备注。
- `category`：默认 unclassified。
- `ingest_status`：保存状态。
- `received_at`、`created_at`、`updated_at`。

现有研究条目的 `metadata` 保存消息 ID、来源和展示字段。微信消息以 `msgid` 为身份，研究条目使用本地消息 ID 建立 canonical URL，避免相同 URL 覆盖不同备注。

## 8. 接口设计

### 微信入库

`POST /api/topics/wechat/messages`

新增输入：msgid、sender_id、message_type、text、original_url、raw_payload。

行为：校验权限和消息大小，按 msgid 幂等入库，返回消息 ID、分类和保存时间。

### 后台列表

`GET /api/topics/wechat/messages?category=unclassified&cursor=...`

支持分类、归档状态和分页，不把连接状态混入消息列表。

### 后台编辑

`PATCH /api/topics/wechat/messages/{id}`

仅允许编辑 title_override、note_override、category。原始消息不可修改。

### 通道状态

`GET /api/topics/wechat/connection`

返回插件启用状态、最近心跳、最近成功入库和最近错误；不包含账户凭据。

现有归档与创建任务接口继续复用。

## 9. OpenClaw 技术架构

```text
微信私聊
  ↓ 腾讯 iLink / 长轮询
OpenClaw Gateway + 微信插件
  ↓ 受限本地调用
视频号选题收集 Agent
  ↓ HTTP，仅 127.0.0.1
消息入库 API + 权限校验 + msgid 幂等
  ↓
wechat_topic_messages ↔ wb_research_items
  ↓
后台待分类 / 编辑 / 归档 / 创建任务
```

权限原则：

- 不使用通用 Agent 自由执行聊天指令。
- 关闭浏览器、发布、文件任意写入和 Shell 权限。
- 消息正文只作为数据参数，不作为系统提示词。
- 凭据留在 OpenClaw 状态目录，不写入项目仓库、日志或研究条目。

运行条件：电脑、OpenClaw Gateway 和本地服务必须运行。没有成功回执即不代表已保存。

## 10. 异常处理

- 重复 msgid：返回首次保存结果，不新增记录。
- 非授权发送者：拒绝并记录安全事件，不返回内部错误细节。
- 无链接：保存文本或附件信息，标记“待补链接”，不阻塞后台分类。
- 无法识别卡片：保存可获得的原始内容，并提示用户在后台补充链接。
- 本地接口不可用：微信回复保存失败；恢复后由用户重新发送，不假装离线同步成功。
- 平台结构变化：页面显示错误位置、类型和处理方式，不自动反复重试。

## 11. 验收标准

1. 微信发送“链接 + 想法”后，后台出现一条待分类记录，微信收到真实成功回执。
2. 微信只发送想法、不发送链接，也能在后台编辑和分类。
3. 后台修改标题、备注和分类，重启服务后仍保留，原始消息不变。
4. 同一 msgid 重放不重复；同一 URL 新 msgid 可以记录新想法。
5. 非授权发送者不能入库。
6. 本地服务停止时不出现成功回执。
7. 分类后的条目可复用现有“创建任务”流程，且来源仍能追溯到微信消息。
8. 分享卡片按实际测试结果标注支持或待补链接，不夸大兼容性。

## 12. 分阶段搭建

### 第 1 步：后台待分类

完成待分类列表、标题/备注/分类编辑和持久化，先用现有手动表单验收，不依赖微信。

### 第 2 步：消息幂等和权限

增加消息表、msgid 去重、发送者校验、连接状态和错误回执。

### 第 3 步：安装与扫码

安装兼容版本 OpenClaw 和微信插件，扫码登录，只允许本人账号。

### 第 4 步：真实私聊验收

依次测试链接+备注、纯备注、重复消息、相同链接新备注和非授权发送者。

### 第 5 步：卡片与长期运行

测试视频号、抖音分享卡片，按结果开放能力；最后配置开机启动和断线可见状态。
