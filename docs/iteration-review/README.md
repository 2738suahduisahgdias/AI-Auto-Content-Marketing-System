# 映序逐页功能评审与迭代资料夹

> 后续统一维护入口已迁移至 `/Volumes/Samsung_T5/AI/映序开发日志/开发版本记录/`。本目录仅作兼容备份，请优先使用新目录中的 `index.html`、`VERSION_INDEX.md` 和迭代记录。

## 打开方式

直接双击 `index.html`，无需启动映序、Node 或任何网络服务。

- 左侧逐页切换：一次完整 review 一个页面。
- “展开全部”：连续查看全部页面。
- 顶部搜索：查找页面、卡片、按钮、输入限制或技术名称。
- 卡片标题：折叠或展开当前卡片。
- review 勾选：保存在当前浏览器本机存储，不上传。
- “迭代记录”：查看每次变更、验证证据和未验证项。
- “打印”：打印当前页面、展开后的全部页面或迭代记录。

## 功能编号规则

- 格式：`P页码-C卡序号-F功能序号`，例如 `P04-C03-F02` 表示第 4 页、第 3 张卡片、第 2 个功能。
- 编号与 `data/pages.json`、离线 HTML 和 `docs/FUNCTION_IDS.md` 一致，当前 26 个页面单元、295 个功能均有唯一编号。
- 修改功能时保留原编号；新功能在对应卡片末尾追加，不重排或重用旧编号。删除功能时在迭代记录中保留原编号及删除原因。
- 每次迭代在记录中列出受影响编号，便于精确更新对应卡片、测试和截图。

## 每次迭代必须执行

1. **修改前看现状**：在 HTML 中确认页面、卡片、控件、限制和技术关系，不凭印象开发。
2. **更新功能事实**：修改 `docs/FUNCTION_MATRIX.md` 后，执行：

   ```bash
   node docs/iteration-review/scripts/sync-pages.mjs
   ```

3. **更新截图**：界面变化时重新采集受影响页面，保留真实空状态和真实测试数据；不要覆盖成设计图或演示结果。
4. **更新 HTML 迭代文档**：在 `data/iterations.json` 中追加本次完整记录并重新生成 `index.html`。**不要为每次迭代新建 Markdown 文件**。HTML 中的“查看本次记录”链接到当前 HTML 内的对应锚点。
5. **重新生成 HTML**：

   ```bash
   node docs/iteration-review/scripts/build.mjs
   ```

6. **实际验收**：检查导航、搜索、截图、记录链接、勾选状态和打印；记录未验证项，不把文档更新当成功能通过。
7. **同步项目记录**：更新 `PROJECT_MAP.md`、`docs/CHECKS.md`、`CHANGELOG_AI.md` 以及受影响模块说明。

## 迭代记录内容要求

每次记录至少包含：修改背景、影响页面和卡片、实际变更、旧数据兼容、验证证据、未验证项、已知风险、回滚方式和下一步。保存、登录、生成、预填和公开发布必须分别描述，不得混写为“完成”。

历史记录只追加，不用新结论覆盖旧记录。若同一功能再次变化，在新记录中说明替代了哪一条旧结论及原因。
